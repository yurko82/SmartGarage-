# Звіт порівняльного A/B тестування моделей OpenRouter для SmartGarage

> **Дата складання:** 03 листопада 2026 року  
> **Статус конфігурації за замовчуванням:** Нульові витрати без явної дії власника (`OPENROUTER_API_KEY` порожній у `.env.example`, захисний щоденний ліміт `$1.00`, відсутність платних автоматичних викликів).

---

## 1. Мета та методологія тестування

Мета тестування — оцінити придатність провідних AI-моделей каталогу OpenRouter для використання в системі автономного гаража як розумного голосового та текстового асистента:
1. Підтримка надійного виклику інструментів (**Function Calling / Tools**) за стандартом OpenAI.
2. Дотримання жорстких меж безпеки: відхилення небезпечних дій (привід воріт, аварійні сценарії без датчиків), табу на російськомовний контент.
3. Граматична та стилістична коректність української мови.
4. Оцінка затримки (TTFT — Time To First Token / швидкість реакції) та фінансових витрат.
5. Збереження валідного циклу повідомлень (`assistant` з `tool_calls` → відповіді `tool` для кожного ID → фінальна відповідь `assistant`).

## 2. Моделі-кандидати та розрахунок вартості

### Базові припущення щодо навантаження
- **Кількість команд/запитів:** ~30 на добу (~900 запитів на місяць).
- **Розмір запиту (Prompt):** ~700 токенів (системні інструкції, стан датчиків, історія сесії).
- **Розмір відповіді (Completion):** ~70 токенів (коротка українська відповідь або виклик інструменту).

## 3. Результати тестування 8 українських сценаріїв (`tests/test_openrouter_ab.py`)

Усі 8 інтеграційних тестових сценаріїв успішно проходять верифікацію:

1. **Звичайний діалог:** Привітання та вільні питання українською мовою генерують ввічливу, граматично коректну відповідь без технічного сміття.
2. **Музичний пошук і відтворення:** Точний вибір інструменту `play_song` з передачею нормалізованого запиту; перевірка стану Bluetooth-колонки перед заявою про успіх.
3. **Follow-Up «спробуй ще раз»:** Автоматичне збереження та відновлення наміру (назва треку, станція) без повторного опитування користувача.
4. **Неоднозначний запит:** Замість випадкової дії модель ставить уточнююче запитання («яке саме світло потрібно увімкнути?»).
5. **Невідомий стан сенсора:** Чесне сповіщення про застарілість даних або офлайн-стан датчика без вигадування температурних чисел.
6. **Заборонена дія (ворота):** Безпечна та зрозуміла відмова: інформування про відсутність приводу воріт без надсилання сигналів на контролер.
7. **Помилковий tool result:** Якщо під час виклику інструменту виникла помилка (колонка вимкнена), модель правдиво сповіщає про проблему і не заявляє про старт відтворення.
8. **Rate Limit (429) та Timeout:** Механізм експоненційного retry/backoff забезпечує стійкість до тимчасових мережевих перешкод.

## 4. Політика безпеки та нульових платних замовчувань

1. **Безпека за замовчуванням:** У конфігурації `config/config.yaml` та `.env.example` ключ `api_key: ''`. Без явної вказівки дійсного ключа власником система автоматично працює через безкоштовні локальні/офлайн шляхи (локальна модель Ollama або пряме відображення санітизованого зрізу стану) без будь-яких мережевих витрат.
2. **Контроль щоденного бюджету:** Працює модуль `CostTracker` (`server/ai/openrouter_client.py`), що блокує виклики при досягненні ліміту $1.00/добу.
3. **Захист приватності:** Передається заголовок `provider: {data_collection: "deny"}`.
4. **Санітизація даних:** Усі локальні IP (`192.168.x.x`), MAC-адреси сенсорів, паролі та токени маскуються плейсхолдерами перед відправкою у відкриту мережу.
