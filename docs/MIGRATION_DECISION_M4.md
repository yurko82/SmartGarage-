# Довідка для власника щодо архітектурних рішень (Фаза M4)

## 1. Питання використання Open Interpreter
### Поточний стан:
* Бібліотека `interpreter` використовується виключно як необов'язковий локальний fallback у розробницькому режимі (`ENABLE_OPEN_INTERPRETER=true`).
* У продакшн-середовищі за замовчуванням `ENABLE_OPEN_INTERPRETER=false` (безпечний режим, захист від довільного виконання коду).
* Основна робота AI виконується через прямий клієнт `OpenRouterClient` (Gemini, Claude, GPT через OpenRouter) та локальну модель `Ollama`.

### Що зміниться у разі повного видалення Open Interpreter:
1. **Зменшення обсягу віртуального оточення:**
   * Звільнення ~1.5 ГБ дискового простору.
   * Видалення важких залежностей: `litellm`, `selenium`, `pyteomics`, `matplotlib` та супутніх компільованих бінарників.
2. **Що втрачається:**
   * Автоматичне написання та виконання Python-скриптів на хості самими LLM (у гаражній системі цей функціонал не використовується для безпеки).
3. **Рекомендація:**
   * Залишити чистий `OpenRouterClient` + `Ollama fallback` як основний рушій інтелекту, вилучивши важкий `interpreter` у майбутніх версіях.

## 2. Питання уніфікації веб-інтерфейсу (Front-end)
### Поточний стан:
* Зараз у системі існують два паралельних інтерфейси:
  1. `index.html` + `app.js` — класичний веб-інтерфейс з швидким керуванням світлом, воротами, проектором та журналом дій.
  2. `dashboard.html` + `dashboard.js` — розширений дашборд з радіостанціями, графіками телеметрії Chart.js, BLE-присутністю та інтерактивними чіпами.

### Що спільного:
* Авторизація за PIN-кодом (`X-Admin-PIN` / cookie).
* Кнопки швидкої дії (Світло, Ворота, Телеметрія).
* SSE (Server-Sent Events) оновлення стану в реальному часі.

### Що унікального:
* В `index.html`: компактний мобільний вигляд для швидкого відкриття з телефону.
* У `dashboard.html`: повний мультимедійний пульт (Radio Browser, регулювання гучності, графіки температури/вологості/батарей датчиків).

### Рекомендація:
* Зберегти обидва шаблони, але винести спільну логіку (REST API запити, PIN модальне вікно, SSE-підключення) в спільний ES-модуль `static/js/api.js`.
