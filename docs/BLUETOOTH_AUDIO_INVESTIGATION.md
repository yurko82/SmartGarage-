# Звіт та стан налаштування Bluetooth-аудіо (JX-BT & JBL)

**Дата:** 17 вересня 2026 р.  
**Статус:** Призупинено для продовження пізніше (`paused_to_continue_later`).  
**Ціль:** Стабільна трансляція інтернет-радіо та музики на колонку `JX-BT` (1-й поверх) через веб-дашборд та голосові/текстові команди.

## 2. Хронологія та виконані роботи

### 2.1. Пошук та реєстрація пристрою JX-BT
* Проведено сканування ефіру через `bluetoothctl`. Знайдено пристрій `00:11:22:33:44:01` з назвою `JX-BT`.
* Пристрій додано в системну пам'ять:
  * [`devices/bluetooth_devices.json.example`](../devices/bluetooth_devices.json.example)
  * [`memory/memory.json.example`](../memory/memory.json.example)

### 2.2. Інтеграція Інтернет-Радіо та виправлення маршрутизації
* Додано сервіс `RadioService` ([server/services/radio_service.py](../server/services/radio_service.py)) з каталогом українських радіостанцій (Kiss FM, Hit FM, Radio ROKS тощо) через Radio Browser API.
* **Багфікс маршрутизатора:** у [server/commands/processor.py](../server/commands/processor.py) команди виду *«включи радіо kiss fm»* раніше помилково перехоплювалися парсером YouTube-відео (через ключове слово «включи»). Додано виключення для «радіо»/«radio», тепер запити гарантовано запускають стрім онлайн-радіо.
* **Оновлення дашборду:** у [server/templates/dashboard.html](../server/templates/dashboard.html) та [server/static/js/dashboard.js](../server/static/js/dashboard.js) додано чіпи радіостанцій, підтримку динамічної назви підключеної колонки та повзунок гучності.

## 3. Виявлені проблеми та технічні причини

### Проблема 1: Звук грав «ривками», заїкався
1. **Шумодав (Noise Gate):** системна гучність у PipeWire була наднизькою (13–20%, -52 dB). Апаратний цифровий шумодав на чіпі приймача глушив звук на тихих ділянках і різко вмикав його на басах.  
   *Виправлено:* зафіксовано базову гучність на рівні **75–80%**.
2. **Невідповідна буферизація GStreamer:** запуск `playbin` з `buffer-duration=3000000000` на живому онлайн-потоці змушував GStreamer постійно прискорювати або сповільнювати відтворення (ефект «гумового» або «завиваючого» звуку).  
   *Виправлено:* прибрано штучний буфер часу, залишено стандартний потоковий потік.
3. **Конфлікт проміжних аудіосерверів:** плеєр використовував `pulsesink`, що викликало розсинхронізацію тактового генератора між PipeWire та PulseAudio-емуляцією.  
   *Виправлено:* у [server/devices/bluetooth_speaker.py](../server/devices/bluetooth_speaker.py) плеєр переведено на нативний `pipewiresink target-object=...`.

### Проблема 2: Падіння в телефонний режим 8 кГц (HSP/HFP CVSD)
* При спробі відтворення WirePlumber автоматично перемикав профіль Bluetooth-карти у `headset-head-unit-cvsd` (монофонічний телефонний дзвінок низької якості).
* *Виправлено:* створено файл конфігурації `~/.config/wireplumber/bluetooth.lua.d/51-bluez-a2dp-only.lua`, який повністю вимикає `hfp_hf/hsp_hs` та блокує з'єднання виключно у високоякісному стерео-режимі **A2DP**.

### Проблема 3: Звук «завився і зник» (Stalled ACL / TX Timeout)
* Для вирішення повідомлення ядра `BCM: firmware Patch file not found` було завантажено патч `BCM20702A1-0a5c-21f4.hcd`.
* **Причина збою:** Апаратний чіп у ноутбуці — це ревізія **BCM20702A0** (`bcdDevice 1.12`), тоді як патч був для новішої ревізії **A1**.
* Через несумісність ревізій у ядрі виникли помилки:
  ```text
  [ 8651.908718] Bluetooth: hci0: link tx timeout
  [ 8651.908737] Bluetooth: hci0: killing stalled connection 00:11:22:33:44:01
  ```
  Чіп зависав після відправки ~100 пакетів і скидав лінк.

## 4. Скрипти керування, створені в проєкті

1. **[`scripts/install_bt_firmware.sh`](../scripts/install_bt_firmware.sh)** — скрипт завантаження та копіювання мікропрограми Broadcom у `/lib/firmware/brcm/`.  
   * **⚠️ ВАЖЛИВЕ ЗАСТЕРЕЖЕННЯ:** Скрипт призначений **виключно** для адаптерів ревізії **BCM20702 A1**. На поточному сервері встановлено ревізію **BCM20702 A0** (`bcdDevice 1.12`), на якій цей патч спричиняє критичне зависання Bluetooth-лінка (`link tx timeout` та `killing stalled connection`). З цієї причини скрипт містить обов'язкове інтерактивне підтвердження (або прапорець `--force`) і його **НЕ слід** застосовувати на цій апаратній конфігурації.
2. **[`scripts/remove_bt_firmware.sh`](../scripts/remove_bt_firmware.sh)** — скрипт видалення несумісного файлу прошивки та повернення до стабільного заводського ROM ядра:
   ```bash
   ./scripts/remove_bt_firmware.sh
   ```

## 5. План дій на наступний сеанс (Чек-лист з фактичними статусами)

- [x] **Крок 1. Відкат прошивки (Виконано):**  
  Несумісний файл `/lib/firmware/brcm/BCM20702A1-0a5c-21f4.hcd` видалено з сервера, стек `btusb` працює на заводському ROM (build 0000). Відсутність файлу в системному каталозі перевірена та підтверджена.
- [x] **Крок 2. Фізична перевірка приймача JX-BT (Виконано):**  
  Приймач JX-BT успішно увімкнено, з'єднання через `bluetoothctl` встановлено (`00:11:22:33:44:01 Connected: yes`).
- [x] **Крок 3. Тест аудіовиходу (Виконано):**  
  Створено PipeWire sink `bluez_output.41_42_62_69_51_9B.1`, стан `RUNNING`. Рівень гучності встановлено на 80% (-5.71 dB) для уникнення спрацьовування апаратного цифрового шумодаву (noise gate).
- [x] **Крок 4. Захист та запуск інтернет-радіо через API (Захищено та покрито тестами):**  
  Ендпоінт `/api/radio/play` та метод `BluetoothSpeaker.play_stream` захищено allow-list валідацією URL схем (дозволено виключно `http://` та `https://`, спроби передати локальні шляхи чи `file://` відхиляються з HTTP 400). Покритий unit-тестами. Запуск радіо після встановлення BT-з'єднання:
  ```bash
  curl -s -X POST http://localhost:5000/api/radio/play -H "Content-Type: application/json" -d '{"station": "kiss_fm"}'
  ```
- [x] **Крок 5. Порівняльний тест A/B (Успішно перевірено):**  
  Перевірено роботу обох колонок:
  * **JBL Clip 5** (`00:11:22:33:44:02`) у гаражі — звук чистий, стабільний.
  * **JX-BT** (`00:11:22:33:44:01`) на 1-му поверсі — успішно підключено, передача пакетів активна, радіо транслюється в реальному часі.
